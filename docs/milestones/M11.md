# M11. Verify

## The problem it addressed
Legacy phase 6 step C recorded problems and let the run go on (OVERVIEW §0, findings 1 and 2). It checked less
than its docstring claimed: no out-of-bounds or tracking checks, and "starts healthy" read `event_state()`, so six
eversys health states that start at 100 passed. M10 built twins that hit their median life at prior medians, but
only static gates stopped a run. M11 adds a verify phase whose checks stop the run, or quarantine one component
while the rest goes on. It also measures the legacy twins with the same checks, the baseline M15 compares against.

## What was built
- **Shared static checks** (`kaful/twin_checks.py`): the build gates moved out of `p5_build/d_check.py`, with the
  same messages in the same order. Build and verify both call them; verify adds provenance (no prior rests on an
  `example` value).
- **VerificationReport schema 2** (approved): results per (target, check), the simulation runs, a quarantine
  entry per component (checks, reason, dependents) and `recheck`. It passes when every failing target is
  quarantined and the recheck is clean, or when failures were allowed. A quarantine with no recheck never passes.
- **Backend:** a simulation returns `event_state` and `threshold_met` per step. The renewal-count state is named
  in the twin model (`renewal_state`), not inside the ProgPy adapter.
- **Verify phase** (`kaful/phases/p6_verify/`, no LLM):
  - `a_recheck_static`: the static gates and provenance on the loaded artifacts;
  - `b_simulate`: four runs with no noise, at a step of the shortest median life / 500:
    `nominal@q0.5`, `documented_maintenance@q0.5`, and `documented_maintenance` at q0.05 and q0.95 (every
    parameter at that quantile);
  - `c_check_dynamics`: per component, over every run:
    - `starts_healthy`: D = 0, health 1.0, no event at t=0;
    - `finite_bounded`: on raw D, because the output health is clipped (correction b);
    - `monotone`: D falls only at a reset or renewal;
    - `event_agreement`: for a threshold renewal, the event first holds at the first renewal (correction c);
    - `maintenance_resets`: replace leaves D = 0, clean and descale D·(1 − recovery), renewal +1 at D_limit;
    - `life_consistency`: on the nominal run only, ±1% of the median life, too fast and too slow both fail;
  - `d_quarantine`: a component failing a dynamic check, and anything it feeds, leaves the twin. Checks a–c
    re-run on the reduced twin. A static or composite failure is never quarantined: it stops the run.
- **Outcomes:**
  - `passed`;
  - `quarantined`: the run goes on with the reduced twin; the manifest lists each component and why. A
    quarantined verify phase is reusable as a base run;
  - `failed`: the run stops;
  - `--allow-failures`: nothing is quarantined, and `allowed_failures` is recorded.
  Verify saves the report and the verified `twin_definition`, which later phases use.
- **Onboarding review:** a verify section, quarantined components first, each with the check, measured against
  limits, and how to resolve it.
- **Legacy baseline** (`kaful verify legacy-baseline <machine>`, a tool):
  - It probes each legacy full-model component and the legacy composite in the sandbox, with nominal inputs of
    1.0, dt = 1, for 1000 steps, as legacy step C did.
  - The checks are `loads`, `starts_healthy`, `finite_bounded` (spec bounds; degradation states in [0, 1]),
    `monotone`, `event_agreement` and `tracking_converges`. `life_consistency` is skipped (not assessable), and
    `provenance` fails (legacy parameters have no source).
  - It writes `outputs/legacy_verification/legacy_baseline.json`.
- **Sandbox** (Natalie, 2026-11-13: only the committed driver, by path and content hash):
  - `kaful/sandbox/drivers.py` pins `legacy_probe.py` by repo path and sha256.
  - `run_driver` refuses a name that isn't pinned or a file whose hash changed. Its target must be a file
    inside the machine directory.
  - The child checks the hash again before loading, which closes the gap between the parent's check and the
    load. `SandboxResult` records the target path and hash.
  - The probe imports no kaful and never touches `sys.path` (rule 7). A legacy composite adds its own folder.
- **Settings:** `VerifySettings`: life band, steps per shortest life, corner quantiles, damage tolerance, step cap,
  and the legacy steps and settle tolerance.

## Surprises
- **`report.passed` was True when every component was quarantined**, because there was no recheck to fail. A test
  caught it. The rule now is that a quarantine without a recheck never passes.
- **The recheck flagged the quarantined component as "not bound"**, because the ParamSet still lists it. Only the
  components in the quarantine list are exempt from that check.
- **The first probe added a folder to `sys.path`**, which the independence test (rule 7) caught. The line wasn't
  needed and was removed, and the probe was re-pinned. The rerun gave identical baseline numbers.
- **`--from verify` leaves the run `not_implemented`**, because it also selects synthesize through evaluate. The
  verify phase itself passed; `--only verify` gives a clean run status.
- **The Mac's maintenance sleep, on battery, froze test runs midway.** The long runs went under `caffeinate -i`.
