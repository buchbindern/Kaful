# M10b. Base-run selection and run-record fixes

## The problem it addressed
The M0–M10 walkthrough (2026-11-12) found three bugs in how a run reuses and records earlier work. A fourth
gap turned up while checking the walkthrough merge. None of them changed a twin, but each made the run record
or the test suite less trustworthy:
- **Auto base-run selection never worked.** `start_run` took an `index_hash` argument that no caller passed.
  Every base run that had been through ingest therefore looked different (`index_hash: <hash> -> None`), and
  every explicit `--base-run` recorded a false "inputs differ" override.
- **A changed input artifact crashed the run.** The edit was caught, so nothing was built on it. But the
  process died with a traceback, and the manifest stayed `running`, with no record of why.
- **The ledger called a final failure a retry.** The second invalid reply was logged as `status: retry`,
  although no retry followed it.
- **One locked prompt's eval recordings were never committed** (`parameterize.life_judgement`, M9), so
  `pytest -m evals` passed locally and would fail on a fresh clone.

## What was built
- `kaful/runs.py`:
  - `input_differences` compares input files **and the config snapshot** (`config_differences`: one line per
    differing setting, e.g. `config understand.n_samples: 3 -> 5`).
  - It no longer compares an index hash. `select_base_run` takes the config instead of an index hash.
  - New `ArtifactMismatch(ValueError)`, raised by `load_artifact` on changed bytes or a wrong kind.
- `kaful/pipeline.py`:
  - `start_run` lost its unused `index_hash` parameter. A run that starts after ingest takes the base run's
    index hash, as before.
  - `_run_phase` records an `ArtifactMismatch` as a failed phase (`artifact: <path>: content does not match the
    recorded sha256`), and the run finishes `failed`.
- `kaful/retrieval/index.py`: `load_vectors` raises `ArtifactMismatch`, and `IndexMismatch` (`--strict`) is
  now an `ArtifactMismatch`, so it is recorded the same way.
- `kaful/llm/gateway.py`: the final invalid attempt is ledgered as `status: error` (`LAST_ATTEMPT = 2`), for
  sync calls and batch rounds.
- `evals/recorded/parameterize.life_judgement/` (v1 and v2, 10 files) is committed.
- **Tests, each written to fail first:**
  - `test_kaful_runs.py`: auto selection with an ingested index; a config change blocks auto reuse and is
    recorded on explicit reuse;
  - `test_kaful_pipeline_mismatch.py`: a changed reused artifact, and a strict index mismatch, each fail the
    phase and the run;
  - `test_kaful_llm_gateway.py`: `[retry, error]` for sync and batch;
  - `test_kaful_eval_recordings.py`: every locked prompt has recordings under its version, all committed.

## How to see it working
- `pytest -q tests/unit/test_kaful_runs.py tests/unit/test_kaful_pipeline_mismatch.py tests/unit/test_kaful_eval_recordings.py`
- `kaful run <machine> --from scope` now picks the latest passing run when its inputs and settings match.
  It refuses with the exact differing files or settings otherwise.

## Measurements
- `pytest -q`: 698 → 704 passed (6 new tests), offline.
- `pytest -m evals`: 14 passed, offline.
- API spend: $0.

## Your decisions
- Compare the config snapshot in base-run selection: refuse in auto mode, record it on an explicit reuse.
- Park the code-version comparison (comparing commits would block auto mode after every commit).
- Add the guard test so uncommitted recordings can't recur.

## Deferred and open
- Code-version comparison: parked in PLAN.md, with a suggestion (a version per phase).
- The config comparison covers every setting in the snapshot, including ones that don't change outputs
  (`default_budget_usd`, `log_level`). A change to those also blocks auto reuse; use `--base-run` (recorded).
  Narrowing the comparison to output-affecting settings would need a list per phase, like the parked
  per-section machine.toml comparison.
- The existing runs' manifests still carry the false `index_hash: … -> None` override text. They are records
  of what happened and are left as they are (no regeneration).

## Surprises
- PLAN.md framed the first bug as "pass the current index_hash". There is no current index outside a run,
  so the fix removes the comparison instead.
- A strict index mismatch crashed the same way as a changed artifact. It's fixed by the same exception.
