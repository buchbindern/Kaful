# M14. Evaluate

## The problem it addressed
Every phase up to estimate wrote artifacts and some tools scored them, but nothing put the numbers together, and
nothing said how far they can be trusted. M14 adds the evaluate phase. It produces one report per lineage, built from
saved artifacts and files only, with no API call. The report covers:
- grounding;
- prompt quality;
- twin quality against the legacy baseline;
- forecast calibration on synthetic truth;
- sensitivity, and which data would narrow it;
- cost against the M1 baseline.

The report states plainly that synthetic data is a sanity check (partly circular), and that absolute rates are checked
for consistency, not accuracy.

## What was built
- **`EvaluationReport` schema 2** (approved 2026-11-17).
  - Every number names the file it came from, with that file's sha256.
  - A section the lineage never reached is listed with the reason, never left silently empty.
  - The three disclaimers are fixed text, enforced by the model.
  - A computed summary leads the report.
- **Evaluate phase** (`kaful/phases/p9_evaluate/`, steps a–g):
  - `a_resolve_lineage`: per phase, its status and the run that produced its artifacts.
  - `b_grounding`: evidence quotes by verification class and code downgrades, walked over the typed artifacts.
    - Also: parameters by source and role, and the life statements behind calibrated lives.
    - Also: the M6 quote set's page coverage for the index the lineage used.
  - `c_prompt_quality`: per prompt version the lineage called (read from the producing runs' ledgers), its lock and
    the per-run eval scores behind it, plus the machine's understand golden score.
    - air_compressor is labelled hold-out.
  - `d_twin_quality`: verification per component with M11's definitions (dynamic = every check but life and
    provenance), beside the legacy baseline.
  - `e_cost`: per phase, the producing run's billed cost, plus the unbilled cost of its cache hits.
    - A cold run is given as a range: from every cached LLM call batched (pricing.toml ×0.5) to none batched.
    - Also: the machine's development spend.
    - Also: the M1 baseline (`docs/m1_baseline/summary.toml`, each figure checked against `docs/m1_cost_baseline.md`).
      Every legacy step is mapped to a phase in `settings.evaluate.legacy_step_phases`.
  - `f_calibration`: covered below.
  - `g_sensitivity`: covered below.
- **Calibration** (`f_calibration`, the only evaluate step that reads truth). It covers every forecast and every
  quantity:
  - **Quantities:** each event (the next limit crossing after the issue time). For parts on one shared channel, the
    label-invariant first failure of the group.
  - **Classes:** each (unit, issue) is covered, missed, censored covered, censored missed, already triggered, or
    undecidable.
    - "Censored": no true crossing before the horizon, so the interval must reach past it.
    - Already-triggered pairs are counted apart, with whether the forecast agreed.
  - **Coverage** of the 5–95% interval per issue fraction and pooled.
    - Wilson 95% intervals are given on the pairs and on the units. The units version is the honest one, since pairs
      within a unit are correlated.
  - **Accuracy:** α-λ (α = 0.2, β = 0.5) with the median mass in the band, prognostic horizon, RMSE of the median
    RUL, median |relative error| and median |log(median / true)|.
  - **Sharpness:** median 90% width / true RUL, and each estimator's width / open-loop's on the same pairs.
  - **The 85–95% target** is judged on observed quantities of the particle filter only. Joined and unobserved parts
    are reported apart, labelled circular.
  - **The decidability note** (decided at checkpoint 2) is added when every verdict's interval overlaps the target.
- **Sensitivity** (`g_sensitivity`):
  - **Prior:** each prior's share of var(log RUL) at t = 0. This is M9's computation, now shared in
    `kaful/sensitivity.py`; the parameterize reports are byte-identical.
  - **Posterior:** at the particle filter's last issue, median over units of each part's **life contraction**
    (posterior 90% width of D_limit / k, the identifiable quantity, against its life_nominal prior), and of each
    carried parameter's share of the remaining log time-to-limit spread.
  - **Recommendations:** rules in `settings.evaluate.recommendations` cover a judged life, missing load ratings, a
    dominant default, a shared channel, an unobserved part and a joined part. Parts are ranked by remaining spread
    (prior sd × life contraction). ρ is listed as an estimator assumption.
- **Shared scoring code** (`kaful/scoring/`):
  - `truth.py` is the only shared code that reads truth; a test enforces this.
  - `samples.py` and `groups.py` read no truth.
  - `kaful estimate score` is byte-identical after the move.
- **`kaful evaluate report <machine> --run RUN`** builds the same report for a run that cannot be a base run, such as
  CDV, whose understand failed its gate.
- **Fixed on the way** (decided at checkpoint 1): `load_artifact` turns a schema failure into `ArtifactMismatch`, so
  the phase fails cleanly instead of crashing. The regression test was run red first.
- **Regenerated** (checkpoint 1): air_compressor and CNC synthesize → estimate from the M13b verify runs (`a92d15`,
  `f7d16a`).
  - Their M13 lineages read a schema 3 twin the current code cannot load.
  - The observations and true states are byte-identical to M12, and the estimate scores match M13.

**The headline, in the report's own words:** calibrated but not sharp.
- **Calibrated:** the particle filter's 90% intervals hold the truth 88–100% of the time on every observed quantity.
  At 11–20 units, above vs within the target is not decidable. The intervals are slightly conservative by design.
- **Not sharp:** α-λ almost never passes, and the intervals span roughly 1–2.5× the true RUL.
- **Cause:** wide judged lives (all 3 on CNC, 4 of 6 on eversys) and sparse observations (2 observed parts per
  machine; CNC's two bearings share one channel).
- **What would sharpen it:** documented lives (rated lives, MTBF, replacement intervals; bearing load ratings on CNC)
  and richer channels (any channel on the unobserved parts; a channel that separates the bearings).

## Measurements
- `pytest -q`: 865 (M13b) → 941 passed, offline. `pytest -m evals`: 14 passed. `mypy kaful` is clean (236 files).
- API spend: **$0.** No LLM step; every regeneration ran with `--budget 0.0001`.
- Runtime: the evaluate phase takes about 3 s per machine.
- Determinism: the four reports are byte-identical under `PYTHONHASHSEED` 0 and 1. A unit test covers the same on a
  fixture lineage.

## The most important files
- `kaful/phases/p9_evaluate/phase.py`: the phase, its map, and `evaluate()`, which the tool shares.
- `kaful/phases/p9_evaluate/f_calibration.py` and `helpers/metrics.py`: coverage classes, Wilson, α-λ, horizon,

- `kaful/phases/p9_evaluate/g_sensitivity.py`: life contraction, remaining shares, recommendations.
- `kaful/phases/p9_evaluate/e_cost.py` and `docs/m1_baseline/summary.toml`: cost and the M1 comparison.
- `kaful/artifacts/evaluation.py`: schema 2.
- `kaful/scoring/`, `kaful/sensitivity.py`: shared with the estimate scorer and the parameterize report.

## Surprises
- **The M13 lineages of air_compressor and CNC could not be loaded** (schema 3 twins), and loading them crashed the
  run instead of failing it. Both are fixed: regeneration, and `ArtifactMismatch`.
- **eversys has no manual parameter at all.** Its two calibrated lives rest on cleaning intervals declared in
  machine.toml. The report now shows what calibrated lives rest on.
- **Cache hits are priced synchronously in the ledger.** A naive cold-run cost doubled CNC's real ingest cost.
- **Many forecasts are of parts that had already failed:** 47 of 80 pairs for CNC's first bearing failure, 48 of 80
  for eversys top_piston. The particle filter agreed in 45 and 48 of them; open-loop in 38 and 38. The filter does
  detect failure.
- **An unobserved part's forecast covers only 60% on CNC (spindle_motor).** It cannot know whether the part has
  already failed, so on the few pairs where it had not, the interval sits early. This is reported among the circular
  parts.
