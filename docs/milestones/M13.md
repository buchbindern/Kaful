# M13. Estimate and forecast

## The problem it addressed
The twin could simulate a machine from its priors, but it never learned from data. Legacy phase 7 ran ProgPy's
filters on a composite model whose state order came from sets, so its noise draws changed with the hash seed (M2).
M13 adds the estimators: a particle filter, a UKF for comparison and an open-loop baseline. They are fed one
observation at a time from a `DataSource`, so the same loop serves files now and streams later. Each machine's own
data updates the uncertain parameters jointly with the damage states, and forecasts give the next time each part
reaches its limit, with every sample kept and censoring explicit.

As in M12, the data is synthetic: a **pipeline sanity check, not validation**. The data comes from the twin's own
priors, so good scores show the machinery works, not that the twin is right.

## What was built
- **Where ProgPy is used** (decided 2026-11-16): ProgPy's `ParticleFilter` cannot express our likelihood (one Gaussian
  on every output, every step; no missing channels or alarms), always resamples, and draws from the global
  `np.random`. Its `MonteCarlo` predictor simulates one sample at a time (hours per eversys unit). Its UKF holds one
  input over every sub-step between rows (a maintenance pulse cannot land on its own step), can overshoot the row time,
  and has a constant, unscaled Q. So:
  - ProgPy provides the **model step**: `render` gained binding subsets, per-particle parameters (constant states),
    a switch that leaves renewal at the limit to the estimator, and a vectorized `next_state`. With none of these it
    reproduces the M12 truth exactly (max difference 0.0 on air_compressor and CNC);
  - the filters and the forecast are numpy in **`kaful/estimation/`**, behind `TwinBackend.estimate` / `predict`,
    so a new backend reuses them.
- **Groups** (`groups.py`): parts sharing an observed channel are filtered jointly; parts with no channel form one
  unobserved group whose posterior is its prior moved forward. It is filtered and forecast once, in the open-loop run,
  and shared by every estimator (identical by construction: same particles, same seeds).
- **Particle filter** (`filter.py`):
  - 4,000 particles per observed group; every uncertain parameter the group reads is carried per particle (k is the
    reported posterior; y_healthy, y_limit, noise_sd, damage_limit and recovery are nuisance);
  - systematic resampling when the ESS falls below half; **Liu-West** rejuvenation of the carried parameters on an
    unconstrained scale (log, or logit within bounds), δ = 0.98 (a = 0.9898, h = 0.1425), which keeps their mean and
    covariance, so the posterior can contract, unlike plain roughening;
  - process noise: D is a Wiener process with variance rate ρ²·D_limit·dD/dt, so a new part's time to its limit has
    coefficient of variation ρ = 0.1. **ρ is an estimator assumption, not a physical parameter**; it is flagged in
    every forecast and in the forecast set.
- **Alarm channels as exact crossing observations** (`events.py`, `kaful/observation/first_passage.py`):
  - each particle anchors an alarm-observed part at its last reset; the time from the anchor to the limit is inverse
    Gaussian. Silence on a monitored channel contributes the conditional survival; a report contributes the
    first-passage *density* at the report time, because the alarm fires at the crossing;
  - a report on a channel shared by several parts (eversys W-014 and W-087/88 on one bool) is attributed per
    particle; a renewed part re-anchors at 0, any other is marked failed;
  - `DataSource.monitored_events`: silence counts only on monitored event channels; elsewhere an empty value means
    no data.
- **UKF** (`ukf.py`): Merwe sigma points over D and the transformed parameters, stepped through the backend; linear
  channels only. A group seen only through alarms, or with a part renewed at its limit, runs open-loop under the UKF
  and the forecast says why; a source where no group can use it is skipped and listed in the forecast set.
- **Forecasts** (`predict.py`): every sample moved forward at once. A forecast event is the next time the part reaches
  its limit after t_issue. Per sample: already triggered (failed at t_issue, no renewal rule: RUL 0), censored (no
  crossing before the horizon), or a time. Percentiles are over every sample, censored ones counting as after the
  horizon, so a percentile past it is None.
- **Formats** (approved 2026-11-16): Forecast schema 2 (issue times, counts, percentiles, parameter and health
  summaries, group diagnostics, ignored profile channels, flags), a samples CSV per issue (each event's time and each
  carried parameter, per sample, so M14 can pair them) and a trace CSV per forecast (per row, health and each linear
  channel's expected reading), each named with its sha256; the `forecast_set` kind indexes a run.
- **Estimate phase** (`kaful/phases/p8_estimate/`, no LLM): `a_open_sources`, `b_start_estimators`, `c_filter`,
  `d_forecast`, `e_write`, per source. Issue times at 0.25, 0.5, 0.75 and 1.0 of each source's span. Sources can run
  in parallel workers (`settings.estimate.workers`); results are written in source order.
- **Scoring tool**: `kaful estimate score <machine> [--run]`, the only estimate code that reads truth, writes
  `outputs/estimate_scores/<run>.json`: state error, channel error, life (D_limit / k) against the prior, and
  label-invariant scores for shared channels; and a forecast coverage preview (M14 owns calibration).

## Results
Runs from the M12 synthesize runs with `--only estimate --base-run ... --budget 0.0001` (no LLM step; the base run
differs in the new estimate settings, recorded as an override). 20 units per machine; "closer" counts units where the
posterior median beats the prior median; "covers" counts units whose 90% interval holds the truth.

**eversys** (run c1abf8; the alarm channel only, so the UKF is skipped and listed; "informative": the part reached
its limit inside the window):

| Part | State RMSE, PF / open-loop | PF wins | |log life error|, PF (prior) | PF closer | PF covers |
|---|---|---|---|---|---|
| top_piston (15 informative) | 0.196 / 0.283 | 16/20 | 0.037 (0.928) | 14/15 | 15/15 |
| water_filter (10 informative) | 0.205 / 0.244 | 17/20 | 0.014 (0.799) | 9/10 | 10/10 |

Water_filter is judged on life = damage_limit / k, the identifiable quantity. Its state error stays high because
before its first report only silence is known.

**air_compressor** (run 90f6a5):

| oil separator | 0.044 / 0.044 / 0.118 | 14/20 | 0.100 / 0.129 (0.311) | 15/20 | 18/20 |

**CNC** (run dda247), judged label-invariantly (one housing accelerometer cannot tell the bearings apart):

| Quantity | PF | UKF | open-loop / prior |
|---|---|---|---|
| vibration channel RMSE (mm/s) | 0.020 (wins 20/20) | 0.039 | 0.389 |
| faster bearing's k: |log error|, closer, covers | 0.376, 15/20, 18/20 | 0.866, 11/20, 14/20 | prior 0.888 |
| slower bearing's k: |log error|, closer, covers | 0.200, 17/20, 18/20 | 0.822, 8/20, 14/20 | prior 0.851 |
| first bearing failure: 90% covers | 19/20 | 20/20 | 18/20 |
| per-bearing state RMSE (not identifiable; reported) | 0.260, 0.237 | 0.221, 0.209 | 0.299, 0.302 |

**Exit criteria:**
1. The particle filter's state error is below open-loop's on every observed part (CNC: on the channel's reading),
   and the unobserved groups are identical by construction (shared, and tested).
2. Posteriors move toward the truth: closer than the prior in at least 75% of informative units on every observed
   part (CNC: both of the sorted pair).
3. Coverage is reported (none below 70%); several intervals cover every unit, consistent with slightly wide intervals
   (the grid oracle measured 15-30% wider; ρ adds spread that noise-free truth lacks). M14 reports this against its
   85-95% target, without tuning ρ on synthetic truth.
4. Determinism: air_compressor and CNC phase outputs are byte-identical under `PYTHONHASHSEED` 0 with 1 worker and
   `PYTHONHASHSEED` 1 with 6 workers (360 files each; `forecast_set.json` differs only in the sha256 of forecast files
   that embed their run id); unit tests cover 1 vs 2 workers and both hash seeds on tiny_pump.
5. Truth isolation: estimate's outputs are byte-identical with every truth file deleted or corrupted (tested).

## Measurements
- `pytest -q`: 819 → 865 passed, offline. `mypy kaful` is clean (209 files).
- API spend: **$0** (no LLM step).
- Phase runtime, 20 units: air_compressor 125 s (1 worker) / 44 s (6 workers); CNC 266 s / 94 s; eversys 744 s
  (6 workers; about 40 minutes projected on 1). Eversys is above the projected 10 minutes: its alarm group's
  forecasts at four issue times dominate.
- Outputs per run: 67-81 MB, almost all sample CSVs (1,000 samples x 4 issue times x up to 3 estimators x 20 units).
- Filter health: no update fell below 1% ESS on any machine.

## The most important files
- `kaful/estimation/filter.py`: the particle filter and open-loop, one observation at a time.
- `kaful/estimation/events.py` and `kaful/observation/first_passage.py`: alarms as exact crossing observations.
- `kaful/estimation/predict.py`: forecasts with every sample, censoring and already triggered.
- `kaful/backends/progpy/model.py`: the vectorized model step.
- `kaful/phases/p8_estimate/phase.py`: the phase, per source.
- `kaful/phases/p8_estimate/tools/score_synthetic.py`: scoring against hidden truth.

## How to see it working
```
python -B -m kaful run air_compressor --only estimate --base-run 20261116T145707Z-b38da7 --budget 0.0001
python -B -m kaful estimate score air_compressor
```
Set `KAFUL_ESTIMATE__WORKERS=6` to run sources in parallel. The run writes `forecasts/`, `samples/`, `traces/` and
`forecast_set.json` under `outputs/runs/<run>/estimate/`.

## Surprises
- **One accelerometer cannot tell two bearings apart.** In 7 of 20 CNC units the filter gave each bearing the other's
  rate. More particles and other discounts did not help: the true posterior has two modes, which Liu-West cannot
  hold.
- **1,000 particles were not enough.** The posterior median moved between seeds by 44% of the posterior sd.
- **A rounded clock dropped alarm reports.** Eversys's integer counter can put an event row at the same time as a
  grid row; a report on such a row was ignored. Fixed, with a regression test run red first.
- **The scorer miscounted a failed part.** A part that failed before t_issue and stayed failed has its true next event
  at t_issue, as the forecast's "already triggered"; the scorer looked only after t_issue. And intervals over samples
  with censored (+inf) values must take sample quantiles, not interpolate through infinity. Both fixed in the tool,
  with a regression test for the first.
