# M15. CI, legacy removal, and the verdict against the baselines

## The problem it addressed
The new pipeline had to be judged against the legacy baselines. If it won, the legacy code could be deleted. The
repository also needed CI and a deployment image. M14's headline lineages also ran on prompt versions older than
their locks, so the final numbers first had to come from lineages on the locked prompts.

## The verdict
On eversys and CNC the new pipeline beats the M1 baselines on cost and verification, beats them on grounding by the
M6 ruling, and meets the calibration target. Each number is in the final evaluation reports (runs below), under
the field in the last column.

**Why grounding rests on page coverage (Natalie, 2026-11-17).** This is M6's ruling, not a loosened check. The
fixed quote set was copied from the old index, an LLM transcription that was partly hand-tweaked, so counting its
quotes favours that index. M6 judged ingest by page coverage and a hand review of the quotes only the old index
supports. That review found the information in the new index for 14 of 15 quotes on eversys and 2 of 3 on CNC (the
rest partial). The quote counts stay in the report as reference.

## What was done
- **Headline lineages on the locked prompts, at $0.** eversys and air_compressor were re-run from understand on
  their M14 base runs.
  - Every understand.fault_modes v5 call was served from the v4 reply under the reuse rule (v5 only raised
    max_tokens).
  - Every other call hit the cache.
  - Field by field, every artifact equals the M14 lineage's apart from run ids and the understand report's prompt
    list, so the M14 headline numbers stand.
  - eversys keeps its 11-05 index: re-indexing on extract_page v3 would change the page text (see Surprises).
  - Evaluate reports extract_page v2 as `equivalent_to_lock` (reuse rule).
- **`kaful run --offline`.** No API client is built.
  - A cache miss fails its phase and names the prompt. Before, a miss left the manifest `running`.
  - A batch miss lists each prompt version and step.
- **Stored token counts.** `count_tokens` results are stored per machine (`outputs/token_count_cache/`). Offline runs
  read them, and a missing count is an error, never an estimate. Filling them took free count_tokens calls only.
- **Evaluate additions.**
  - A prompt version that the reuse rule serves under the lock is reported as `equivalent_to_lock`.
  - Page coverage carries the old index's page coverage and quote counts, and the M6 old-only review counts, each
    with its file and sha256.
  - It reads the legacy verification baseline from `docs/legacy_baseline/<machine>.json`.
- **Legacy removal.** Tag `legacy-final` = `5f7b330`, the last main commit with the legacy pipeline. Deleted (342
  files):
  - `phases/`, `run.py`, `utils/`, `prompts/`, the root `config.py`, `rag_frameworks/`, `demo/`,
    `machines/*/queries.py`;
  - 5 legacy scripts;
  - the legacy tests, fixtures and harness;
  - every tracked legacy machine output;
  - `kaful verify legacy-baseline`, with its probe driver and settings.
  - Two kaful tests now pin the legacy prompt hash and v1 ledger rows as captured data.
  - The sandbox's pinned-driver mechanism stays, with an empty registry and tests on a test-only driver.
- **Kept.**
  - The `pre-revamp` and `legacy-final` tags, and `~/Kaful-baselines/`. `demo/report.html` was copied to
    `m15/demo/` there first, since it was not in the M0 tarball.
  - `OVERVIEW.md`, the M1 cost baseline, the M6 grounding results.
  - The M11 legacy baselines, frozen byte-identical in `docs/legacy_baseline/`.
  - Locally: `machines/*/rag/` (the grounding tool's old-index side) and the M1 ledgers.
- **Dependencies.**
  - chromadb, pypdf, duckdb and beautifulsoup4 removed (legacy only).
  - `ruff==0.15.14` pinned.
  - New `constraints.txt` pins every transitive dependency at its pipeline311 version.
- **Lint and types.**
  - ruff is clean on kaful, tests and scripts.
  - mypy checks `tests/` in standard mode beside strict `kaful/`; its 39 findings in the tests are fixed.
- **Docker.**
  - Base: `python:3.11.15-slim-bookworm` pinned by digest.
  - A wheel stage builds what has no prebuilt wheel (numpoly, via ProgPy). The runtime image carries no compiler.
  - `runtime` target: the deployment unit; machines/ is mounted at run time.
  - `test` target: dev dependencies and tests. Both run as a non-root user.
  - No secrets or machine data in the image.
- **CI** (`.github/workflows/ci.yml`; actions pinned by commit SHA):
  - ruff, mypy and the committed-recordings check run on the checkout;
  - `pytest -q` runs inside the test image with `--network none`;
  - the runtime image is built and started.
- **`kaful runs prune <machine>`.** A dry run unless `--apply`.
  - Kept: runs named with `--keep`, runs cited in PLAN.md or a milestone doc, the newest pass of each phase, runs
    that may be live, unreadable runs, and every kept run's lineage.
  - Deleted: failed, stale and superseded runs.
- **Gitignore.** `machines/*/outputs/` as a whole (nothing in it is tracked any more) and `.hypothesis/`.
- **README, `.env.example`.** Rewritten for kaful.

## Deferred and logged
- **The worker-pool stall** (PLAN, follow-up after M15). One local full-suite run stalled for about 3 h at full
  CPU and left a multiprocessing resource tracker behind. It was not reproduced: later local, image and CI runs took
  about 4 min.
  - Give the estimate phase's worker pool a wall-clock limit, so a hung worker fails the phase in the manifest.
  - Look at the multiprocessing start method as a likely cause.
  - Until then, CI's `timeout-minutes` (20 and 45) is the only guard.
- **The prompt version is part of the page text.** Each page's LLM layer starts with
  `[llm layer: ingest.extract_page v2]`, so any version bump changes the embeddings and every downstream prompt's
  cache key. The proposal is to move provenance into page metadata; it is an artifact-format change, to be decided
  later.
- **No M6 quote set for new machines.** `kaful ingest grounding --freeze`, which builds a quote set for a new machine,
  needed the legacy outputs. The frozen eversys and CNC sets still work; air_compressor's could be built from tag
  `legacy-final`.
- **CLAUDE.md.** Its migration section, the legacy-run line and the `pytest -m slow` golden test describe what M15
  removed. The proposed wording is in the checkpoint 4 report. The `slow` marker is kept, with no tests.
- **Base-run reuse after a settings change.** M15 changed the settings snapshot: the legacy-baseline path, the
  removed `verify.legacy_*` settings, and `runs`. Auto base-run selection treats earlier runs as different, so use
  `--base-run`. This is the parked "narrow the settings comparison" item.

## Surprises
- **Offline mode first decided differently from online.** Whether the manual goes in whole depends on its
  count_tokens count. With no API client, the code used a character estimate, which split eversys's 91k-token
  manual into two parts, a different request. Stored counts fixed this.
- **The extract_page version is in the page text.** Re-indexing eversys on v3 would have changed 54 chunks and every
  understand request, although the transcriptions are byte-identical. That is why route B kept the 11-05 index.
- **A fresh install resolved 75 of 130 packages to other versions,** including filterpy 1.4.5 → 2.0.0 under ProgPy's
  filters, because `requirements.txt` pins only direct dependencies. `constraints.txt` fixes it.
- **Git:**
  - a `git add -A` over `machines/` swept 100 untracked tool outputs into a commit;
  - fixing it showed that `git reset` exited 0 without restoring the index, while `git read-tree HEAD` did.
  - The commit was amended before any push; the files are on disk and now gitignored.
- **A miss inside a phase left its run `running`.** That is one reason for the stale runs prune now lists: 8 of
  them on eversys, CNC and CDV.
