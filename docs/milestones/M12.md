# M12. Synthesize

## The problem it addressed
There is no failure data for any machine, so M13's estimators and M14's calibration need data whose truth is known.
Legacy phase 3 had an LLM write a simulator per machine. Its rates were separate from the twin's, and phase 7 never
read the observations. M12 generates synthetic units from the twin's own ParamSet and records the hidden truth:
true parameters, true states, and every time a part reached its limit. The data loads through the same
`DataSource` interface that real data will use. It is labelled a **pipeline sanity check, not validation**: scoring
a twin on data made from its own priors is partly circular.

Synthetic sensor data needs observation models (damage → channel reading + noise). PLAN had them in M13, so they
moved into M12 (Natalie, 2026-11-14). Estimation stays in M13.

## What was built
- **Observation models** (`kaful/observation/`, pure numpy, shared by synthesize and estimate):
  - the protocol: `expected`, `sample` and `log_likelihood` over a `DamageView` (D/D_limit, and whether D reached
    D_limit in each interval);
  - `linear`: y = y_healthy + (y_limit − y_healthy)·clip(D/D_limit, 0, 1) + Gaussian noise. Documents state the
    reading *at* the limit ("exceeds 1 bar"), so each end is its own parameter, and the direction follows from the
    two. A channel several parts act on adds each part's change (`linear_channel`);
  - `threshold_event`: the channel reports when D reaches D_limit (eversys W-014 at each filter renewal). No noise
    in M12.
- **Artifact formats** (approved 2026-11-14):
  - ParamRole `observation`;
  - TwinDefinition schema 3 with `observations`: per (binding, channel) the form, slot → param_id, `event_value`, and
    the scope link that motivated it (`observable_by`, `named_by` or `declared`);
  - SyntheticDataset schema 2 (paths, sha256s, seed, windows; no true value);
  - a new kind, `synthetic_truth`, one per unit: drawn and derived parameters, and per event `first_time`,
    `limit_times` and `in_window`.
- **machine.toml** `[[observation]]` and `[[observation_channel]]` (reviewed, `docs/proposals/M12-observations/`).
  Each value is `value` or `low`/`high` (5–95%), with a source, a ref, and optionally doc_id, page and quote.
- **Parameterize step f** (`f_observation_priors`; the check step became `g_check`):
  - each linear channel gets `machine.<channel>_y_healthy` and `_noise_sd`; each part on it gets
    `<component>.<channel>_y_limit`;
  - quotes are checked by code: a `manual` value whose quote isn't in the page's raw text becomes `deployment`;
  - a judged value scores 0.3× and is flagged;
  - the default noise is 5% of the smallest |y_limit − y_healthy|, flagged;
  - the gate fails if y_limit's 5–95% interval overlaps y_healthy's.
- **Build step d** (`d_bind_observations`; the check step became `e_check`): binds reviewed declarations only. The
  observation gates (channel, form vs dtype, slots, units, one y_healthy and noise per channel) run in build and
  verify (`kaful/twin_checks.py`). Quarantine drops a quarantined part's observations.
- **Understand:** declared `[[instrumentation]]` channels join the SensorContract but are left out of the
  fault_modes prompt, so declaring a sensor changes no LLM input.
- **`FileSource`** (`kaful/data/file_source.py`): a CSV DataSource and its writer, which share one column layout.
  - `t` comes from the usage clock, or from timestamps in the time unit;
  - columns outside the contract are dropped and listed, so truth can't leak in;
  - an unparseable cell is passed on for the contract check to report;
  - `t` going backwards is an error that names the row.
- **Synthesize phase** (`kaful/phases/p7_synthesize/`, no LLM):
  - `a_draw_units`: the parameters the twin reads, drawn from their priors in sorted order; `life_nominal` is
    derived from k, not drawn. Unit i uses `SeedSequence(seed, spawn_key=(i,))`, split into parameter, noise and
    window streams;
  - `b_simulate_truth`: the verified twin under the documented-maintenance profile, on verify's step, noiseless;
  - `c_check_units`: verify's dynamic checks on each unit's truth (they moved to `kaful/dynamics/`);
  - `d_observe`: linear channels on a grid every shortest median life / 50; events at the simulation step where they
    happen, up to the window end. The window ends at Uniform(0.1, 0.6) × horizon, independent of the truth, so the
    censoring tells an estimator nothing about the failure time. Channels with no reviewed model stay empty;
  - `e_write`: `observations/<unit>.csv`, `truth/<unit>.states.csv`, `truth/<unit>.json`, with sha256s.
- **Settings:** `SynthesizeSettings` (seed 20261114, 20 units, profile, window fraction, sampling, timestamp
  origin), and `ParameterizeSettings` gained the observation noise fraction and log-sd.

- the air cooler → element outlet link (the cooler is downstream of the element).

- all 50,400 rows load through `FileSource` and pass the SensorContract check;

## The most important files
- `kaful/observation/forms.py`: the linear and threshold-event forms and their likelihoods, which M13 weighs
  particles by.
- `kaful/phases/p7_synthesize/d_observe.py`: what a unit reports, and its truth events.
- `kaful/phases/p4_parameterize/f_observation_priors.py`: observation priors from reviewed declarations, with
  quotes checked by code.
- `kaful/data/file_source.py`: the CSV DataSource that M13 reads, for synthetic and real data alike.
- `kaful/artifacts/synthetic.py`: the dataset/truth split that keeps truth away from estimators.

## How to see it working
```
python -B -m kaful run air_compressor --only synthesize --base-run 20261116T145200Z-9d5cd5 --budget 0.0001
```
The run writes to `machines/air_compressor/outputs/runs/<run>/synthesize/`: `observations/`, `truth/` and
`synthetic_dataset.json`.

## Deferred and logged (PLAN M12)
- k and life_nominal are independent priors of one quantity; one should be derived from the other.
- Missing physics link: eversys water_filter exhaustion should drive the boilers' scaling rate. This is why
  steam_boiler fails inside the window in all 20 units.
- Positive-only noise for non-negative channels: the separator Δp reads as low as −0.03 bar.
- `error_message` is a bool, so W-014 and W-087/W-088 can't be told apart; a W-code category is an understand
  follow-up.
- STSC (better for bearings) has only colour bands in the thesis figure; LTSC is used.
- Truth is noiseless given the parameters; process noise belongs to M13. Operating conditions stay at nominal
  (f = 1), so units differ by parameters only.
- Many failures fall after the horizon, mostly parts scheduled maintenance keeps healthy. M14 must count them as
  censored.

## Surprises
- **Truth missed repeat crossings.** On air_compressor, 3 units' separators were replaced on schedule and reached
  the limit again, so `service_warning` fired twice while the truth listed one failure. The truth now records every
  limit time (`limit_times`). The regression test was written after the fix; from now on regression tests are
  written failing-first too (logged).
- **The dry run caught a judged value scoring 0.94 confidence.** Judged observation values are now scaled by the
  judgement factor and flagged.
- **Declared channels reached an LLM prompt.** The fix (your proposal) keeps declaring a sensor free and keeps
  scope unchanged.
- **Eversys is mostly counter rows.** Only `error_message` carries information. milk_system reaches its limit
  repeatedly in 4 of 20 units, as the cleaning prior allows (q = 0.20).
